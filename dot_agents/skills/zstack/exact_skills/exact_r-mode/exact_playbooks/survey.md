# Survey

For seeds, papers or a direction that need to become hypotheses. The output is the synthesis.

1. Pin the sources: the exact papers, versions and code. An acronym you cannot resolve is a question for the user, not a guess.
2. Two readers from different model families work in parallel from the same brief: each source's mechanism, what it shows against what it claims, how the ideas combine or conflict, and candidate experiments. Read the primary sources yourself meanwhile; judging the readers needs them.
3. Cross-check. Where the readers disagree, decide from the source and say why. A correction you accept goes into the synthesis with its reason.
4. Write the synthesis: the source table, each of the user's seeds with a verdict, and a candidate pool. Each candidate names its hypothesis, the cheapest experiment that tests it, the result that would kill it, and its cost in GPU-hours.
5. Freeze it when the user says so. Later evidence goes into the rounds and the card; a revised synthesis is a new version.
